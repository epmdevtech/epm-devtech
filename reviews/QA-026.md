## 1. Resumo Executivo

A regressão reportada pelo PO referente ao **deslocamento/estufamento horizontal do Header fixo para o lado direito** ao clicar no seletor "Desafio ou Tipo de Projeto" na seção de Contato (evidenciada na captura `Captura de tela de 2026-09-07 10-40-09.png`) foi investigada em nível de motor de renderização e definitivamente corrigida.

### Diagnóstico Técnico da Causa Raiz:

1. **Injeção Dinâmica em Tempo de Execução via `<style>` tag**:
   - O `@radix-ui/react-select` utiliza internamente a dependência `react-remove-scroll` e `react-remove-scroll-bar`.
   - Ao abrir o dropdown, a biblioteca cria dinamicamente um elemento `<style>` no final do `<head>` via `styleSingleton`, aplicando a regra:
     ```css
     body[data-scroll-locked] {
       overflow: hidden !important;
       margin-right: 15px !important;
     }
     ```
2. **Derrota da Regra CSS Estática por Ordem de Cascata**:
   - Na tentativa anterior (`SPEC-024`), a regra `body[data-scroll-locked]` possuía especificidade `(0, 1, 1)` — rigorosamente a mesma especificidade da regra injetada pela biblioteca.
   - Pelo algoritmo de desempate do CSS (Cascading Rules), como a tag `<style>` da biblioteca era inserida no `<head>` *após* a folha de estilos compilada do Vite/Tailwind, a regra dinâmica vencia, forçando `margin-right: 15px !important` no body.
3. **Desalinhamento Espacial do Header Fixo**:
   - Elementos com `position: fixed; left: 0; right: 0;` (como o `<header>`) posicionam-se em relação ao *viewport* (janela do navegador), e não ao `body`.
   - Com o desaparecimento da barra de rolagem e a aplicação de `margin-right: 15px` somente no `body`, o container centralizado do header recalculava o centro com base na largura cheia (ex.: 1270px), enquanto os containers da página recalculavam o centro com base na largura reduzida (1255px).
   - O resultado era um salto visível de metade do gap (~7.5px) para a direita no header e o aparecimento de uma faixa lateral no rodapé/fundo da página.

---

## 2. Solução Implementada

### 2.1 Elevação de Especificidade CSS (`src/index.css`)

Elevamos a especificidade do seletor estático para `(0, 1, 2)` antecedendo o seletor com `html`:

```css
/* Previne que bibliotecas como Radix/react-remove-scroll ocultem a barra de rolagem e desloquem elementos fixos.
   Especificidade: html body[attr] = (0,1,2) > body[attr] = (0,1,1) da biblioteca.
   Como a react-remove-scroll-bar injeta estilos via styleSingleton APÓS o CSS estático,
   o aumento de especificidade garante que nossa regra sempre vença, independentemente da ordem. */
html body[data-scroll-locked] {
  overflow: visible !important;
  margin-right: 0px !important;
  padding-right: 0px !important;
}

/* Blindagem explícita do Header contra qualquer alteração de right ou margin-right */
html body[data-scroll-locked] header {
  right: 0px !important;
  margin-right: 0px !important;
}
```

Com a especificidade `(0, 1, 2)` para o body e `(0, 1, 3)` para o header, as regras compiladas têm precedência incondicional sobre qualquer folha injetada dinamicamente com especificidade menor.

### 2.2 Blindagem do Teste Automatizado E2E (`e2e/design-system-and-stability.spec.ts`)

O teste E2E do Playwright foi aprimorado para validar não apenas as dimensões do bounding box do Header, mas também inspecionar diretamente os estilos computados do `document.body` no momento em que o dropdown está expandido:
- Confirma que `data-scroll-locked` está ativo no body (`hasScrollLocked: true`)
- Valida que `computed.marginRight === '0px'`
- Valida que `computed.overflow === 'visible'`
- Valida que `Math.abs(headerAfter.x - headerBefore.x) <= 0.5px`
- Valida que `Math.abs(headerAfter.width - headerBefore.width) <= 0.5px`
