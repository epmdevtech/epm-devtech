## 2. Diagnóstico & Causa Raiz

1. **Colisão de Namespace no Tailwind CSS (`textColor` vs `colors`):**
   - As definições de `colors.secondary` e `colors.muted` apontavam para as variáveis de superfícies escuras de fundo (`--bg-elevated-rgb` = `#141D1F` e `--bg-surface-rgb` = `#0F1617`).
   - Classes utilitárias como `text-muted` e `text-secondary` resolviam para a cor de fundo em vez da cor de texto (`--text-muted-rgb` e `--text-secondary-rgb`).
   - **Solução Implementada:** Inclusão explícita de `theme.extend.textColor` no `tailwind.config.ts`, garantindo que `text-primary`, `text-secondary`, `text-muted`, `text-brand` e `text-on-brand` resolvam com precisão para os tokens semânticos tipográficos da Camada 2.

2. **Invisibilidade e Latência do Cursor Orb:**
   - No `Layout.tsx`, o componente `<CursorOrb />` estava envelopado dentro de `<LazyRender delay={2500}>`. Durante os primeiros 2,5 segundos, o cursor nativo já estava oculto via CSS global, deixando o usuário sem qualquer ponteiro.
   - O `z-index` do `CursorOrb` era `z-0`, ficando posicionado atrás de cards, modais e elementos com fundos opacos.
   - A ocultação do cursor nativo não era condicionada à presença do componente ativo no DOM.
   - **Soluções Implementadas:**
     - `<CursorOrb />` desacoplado do `LazyRender delay={2500}` e renderizado imediatamente no shell do `Layout.tsx`.
     - `CursorOrb` promovido para `z-[9999]` com `pointer-events-none`.
     - `index.css` atualizado com escopo condicional: `@media (pointer: fine) { html.custom-cursor-active, html.custom-cursor-active * { cursor: none !important; } }`.
     - Classe `custom-cursor-active` ativada dinamicamente pelo `CursorOrb` em ambiente não-touch e sem reduced-motion.
     - Dot estilizado com raio de 8px, cor sólida `#2DD4BF` e glow `0 0 10px 2px rgba(45, 212, 191, 0.85)`. Ring com borda de `1.5px solid rgba(45, 212, 191, 0.75)` e sombra `0 0 14px 3px rgba(45, 212, 191, 0.4)`.
